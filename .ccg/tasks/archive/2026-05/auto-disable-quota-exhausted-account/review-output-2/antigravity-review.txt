##### ① 重复禁用/并发场景下可能导致 DB 与 Cache 不一致
*   **文件与行号**: [internal/op/quota_disable.go:24-26](file:///Users/chaos/developments/github_go/octopus/internal/op/quota_disable.go#L24-L26)
*   **问题描述**: 
    在 `ChannelKeyEnabled` 函数中，使用 GORM 对 `model.ChannelKey` 执行更新操作：
    ```go
    result := db.GetDB().WithContext(ctx).
        Model(&model.ChannelKey{}).
        Where("id = ? AND channel_id = ?", keyID, channelID).
        Update("enabled", enabled)
    if result.Error != nil {
        return result.Error
    }
    if result.RowsAffected == 0 {
        return gorm.ErrRecordNotFound
    }
    ```
    在并发请求或者先前已禁用的情况下，如果对同一个 `keyID` 再次执行 `enabled = false`，由于数据库记录的 `enabled` 字段已是 `false`，在 MySQL（未设置 `clientFoundRows=true` 时）或 SQLite 中，`result.RowsAffected` 会返回 `0`。
    
    一旦返回 `0`，该函数将直接抛出 `gorm.ErrRecordNotFound` 并提前终止，**导致后面的 `channelCache.Set` 缓存更新以及 `resetBalancerStateForChannel(channelID)` 被完全跳过**。这在并发请求下极易造成内存缓存与数据库状态不一致。
*   **解决方案**: 
    建议放宽或移除 `RowsAffected == 0` 的强一致性限制。因为将本已是 `false` 的 key 再次设为 `false` 是符合幂等性的。可以改为直接根据 `.Error` 进行判断，或仅在确定为 `true -> false` 时需要重置；更简单地，将 `RowsAffected == 0` 从错误检查中移除，仅用来做 debug 日志判定：
    ```go
    // 不应该把 RowsAffected == 0 视作 ErrRecordNotFound，因为可能已经是目标状态
    ```

##### ② 针对 Gemini 等平台的临时 429 限流存在误判定为永久禁用的风险
*   **文件与行号**: [internal/upstreamerr/quota.go:44](file:///Users/chaos/developments/github_go/octopus/internal/upstreamerr/quota.go#L44)
*   **问题描述**:
    在 `keyQuotaSignals` 中包含了 `"quota exceeded"` 和 `"quota_exceeded"` 两个非常宽泛的字符串：
    ```go
    var keyQuotaSignals = []string{
        "insufficient_quota",
        "quota_exceeded",
        "quota exceeded",
        ...
    }
    ```
    部分大模型提供商（特别是 **Gemini / Vertex AI**）在触发临时并发限流或每分钟请求限流（TPM/RPM 429）时，其返回的错误消息常包含 `"Quota exceeded for AI Core API"` 或 `"Resource has been exhausted (e.g. queries per minute limit ...)"`。
    
    这些错误在语义上是**临时速率限流 (Rate Limit)**，理应通过软限流进行自动指数退避重试，但在此处的匹配逻辑中，会被误判为 `QuotaScopeKey`（余额不足），从而**触发永久性的自动禁用**，给运维带来极大负担。
*   **解决方案**:
    在 `ClassifyQuotaExhaustion` 的起始位置，增加针对频率限制的排除规则（Exclusion Rules），如果检测到包含 `rate limit`, `rate_limit`, `per minute`, `rpm`, `tpm` 等敏感词，优先排除：
    ```go
    if strings.Contains(normalized, "rate limit") || strings.Contains(normalized, "rate_limit") || strings.Contains(normalized, "per minute") {
        return QuotaDecision{}
    }
    ```
